## 한 줄 상태

**가격·수급 기반의 결정론적 브리핑은 2주 게이트를 통과했고 매일 동작한다.**
뉴스 점수와 LLM 요약·반증을 안전하게 생산하기 위한 코드 수정은 로컬에서 끝났지만,
아직 커밋·rebase·프로덕션 실행 전이다. 다음 작업은 기능 추가가 아니라 이 변경을
안전하게 반영하고 실제 Actions artifact로 확인하는 일이다.

## 순서가 중요한 이유

LLM 요약은 계산된 등급을 새로 만들면 안 되고, 이미 계산된 등급과 모순돼도 안 된다.
발행 전 검사, 유료 뉴스 점수 영구 저장, 점수 리포트 표시는 구현·테스트됐다. 이제
그 순서를 운영 단계에서도 지킨다.

```
변경 검토·rebase·반영 → Actions secrets 등록 → 첫 CI 검증 → 과거 뉴스 점수 백필
```

미커밋 변경보다 키나 백필을 먼저 적용하면 Actions가 이전 코드를 실행하므로, 검증한
안전장치가 없는 상태에서 산문을 게재하거나 점수를 다시 과금할 수 있다.

## 1. Codex가 끝낸 일 — 발행 가드 검증

`src/report/consistency.py`의 F1을 마무리했다.

- **왜:** 종목을 특정할 수 없는 추천 표현, US 종목 뒤의 추천 표현, `저가매수` 같은
  복합 추천어가 기존 가드를 통과하거나 엉뚱한 KR 종목에 귀속될 수 있었다.
- **어떻게:** 계산된 KR 등급 하나에 유일하게 연결할 수 없는 등급 표현은 ⑤/⑧ 전체를
  생략한다. `순매수`, `매도 우위`, `매수세` 같은 수급 표현은 추천으로 오인하지 않는다.
- **현재:** 이 fail-closed 수정과 단위 테스트가 로컬 작업 트리에 있다. 2026-08-28에
  오프라인 테스트 921개, Ruff 검사·포맷 검사, diff 공백 검사를 통과했다. 다만 아직
  커밋되지 않았으므로, 최종 diff 검토 뒤에야 변경 자체를 확정한다.
- **완료 기준:** `uv run pytest -m "not network"`, `uv run ruff check .`,
  `uv run ruff format --check .`가 모두 통과하고, 렌더된 헤더가 “등급 모순”과
  “등급 검증 불가”를 구분해 보여 준다.

이 변경이 프로덕션에 반영되기 전에는 `ANTHROPIC_API_KEY`를 Actions에 등록하지 않는다.

## 2. Codex가 끝낸 일 — 뉴스 점수를 잃지 않게 만들기

생산 점수 경로를 한 변경으로 완성했다.

- `report.yml`이 이미 존재하는 `DART_API_KEY`와 `SEC_USER_AGENT`를 전달하게 했다.
  KR/US 공시 수집의 실제 복구는 변경 반영 뒤 CI에서 확인한다.
- `data/scores/`를 Actions의 커밋 대상에 포함했다. 이 파일은 유료 LLM 호출 결과라
  재생성해도 되는 캐시가 아니다.
- 점수를 25개 청크마다 저장해, 30분 작업이 중단돼도 성공한 호출을 전부 잃지 않게 했다.
- 변경 반영 뒤에만 `OPENAI_API_KEY`를 등록한다.
