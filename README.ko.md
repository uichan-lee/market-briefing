# market-briefing

한국·미국 주식 데일리 마켓 브리핑 자동 생성. 추적하는 모든 종목에 대해 근거와 함께 방향성 의견을 제시하고, 거기서 멈춘다. **이 시스템은 매매를 실행하지 않는다.**

English: [README.md](README.md)

## 무엇인가

하루 두 번 GitHub Actions가 시장 데이터와 뉴스를 수집하고, 뉴스를 구조화된 숫자로 바꾸고, 피처를 계산해서 한국어 마크다운 브리핑을 만든다. 결과물은 Obsidian vault와 이메일로 전달된다. 그걸 사람이 읽고 판단한다.

| 실행 | 시각 (KST) | 커버리지 |
|---|---|---|
| `RUN_MORNING` | 07:00 | 미국장 마감(전일) + 한국장 프리마켓 — KOSPI 개장 2시간 전 |
| `RUN_EVENING` | 21:30 | 한국장 마감(당일) + 미국장 프리마켓 — 미국장 개장 1시간 전 |

### 나머지 전부를 결정하는 다섯 가지 원칙

1. **의견은 계산되는 것이지 작성되는 것이 아니다.** 브리핑은 모든 종목에 강한 매수 ~ 강한 매도 등급을 매기지만, 그 등급은 z-score 가중합이지 LLM이 쓴 문장이 아니다. LLM은 개별 기사를 고정된 숫자 스키마로 바꾸기만 하고 등급은 보지도 않는다. 이게 의견을 재현 가능하게 만들고, 재현 가능성은 그 의견이 쓸 만했는지 나중에 확인할 수 있는 전제 조건이다.
2. **결정론 우선.** 문자열 매칭, 임베딩 유사도, 통계로 풀리는 건 그렇게 푼다. LLM은 언어 이해가 정말로 필요한 판단에만 쓴다. 이게 결과를 평가 가능할 만큼 재현 가능하게 만드는 핵심이다.
3. **raw 데이터는 불변.** 수집한 원본은 날짜 파티션에 적재하고 절대 덮어쓰지 않는다. 3개월 뒤 이게 백테스트 데이터셋이 된다.
4. **모델은 교체 가능.** 모든 모델 호출은 어댑터 하나를 통과한다. 벤더 SDK는 그 밖에서 import되지 않는다.
5. **평가 기준은 데이터 수집 전에 고정됐다.** [PREREGISTRATION.md](PREREGISTRATION.md) 참조.

### 의도적으로 하지 않는 것

- **주문·체결·취소 API 호출 없음.** 조회 전용 엔드포인트만. 브리핑은 의견을 내고, 판단과 실행은 사람이 한다.
- LLM이 작성한 등급이나 근거 없음 — 둘 다 산술 연산이고 그래서 감사 가능하다.
- 종목 별칭 자동 생성 없음 (잘못된 별칭 하나가 downstream 숫자 전부를 조용히 오염시킨다).
- 3개월 평가 게이트 통과 전 실제 자금 매매 없음.

> **의견과 실행은 다르다.** 이 프로젝트는 둘 다 진지하게 다룬다. 근거를 붙여 "강한 매수"라고 말하는 것이 이 시스템의 결과물이다. 주문을 넣는 것은 결과물이 아니고, 앞으로도 아니다.

**가동 단계.** 결정론적 파이프라인이 수집 → 해석 → 계산 → 등급 → 렌더 → 전달까지 하루 두 번 무인으로 돌고 있고, 2026-08-03부터 그렇게 돌아왔다. `data/raw/`에는 3년치 백필과 2026-08-03에 시작된 실시간 뉴스 기록이 있다. 골든셋과 모델 베이크오프(SPEC §12 7~8단계)는 둘 다 끝났다 — 2026-08-12에 스코어링 모델로 `gpt-5.1`을 골랐다가, OpenAI의 데이터 쉐어링 무료 토큰 프로그램(`gpt-5.6` 계열은 대상이 아님)을 반영해 2026-08-13에 `gpt-5.4`로 교체했다 — 현재 볼륨에서 사실상 무료이면서 품질도 실측상 더 낫다. 아직 없는 건 임베딩 파이프라인(6단계)이고, 이게 없으면 `news_polarity`가 채점할 대상 자체가 없다.

**파이프라인은 오늘 이미 끝에서 끝까지 돈다.** 수집기 → 피처 → 계산된 등급 → 렌더링된 브리핑 → 이메일까지, 하루 두 번 무인으로. 빠진 것은 점수의 *뉴스* 절반이다. LLM 단계(SPEC §12 6~8단계)가 아직 없어서 `news_polarity`가 아무것도 만들지 못한다.

**존재하지 않는 피처 두 개의 가중치를 걷어냈다 (2026-08-08).** `news_polarity`(0.20)와 `rev_4w`(0.15)가 `config/rating.yaml`의 `weights`에 있으면서 계산하는 코드는 없었다. `rate()`가 1.10을 기준으로 재정규화하는데 실제로 도착할 수 있는 건 0.75뿐이었고, `min_weight_coverage: 0.5` 하한까지 여유가 50포인트가 아니라 18포인트였다. 이제 `rate()`가 읽지 않고 리포트 헤더만 읽는 `deferred_weights` 키로 옮겼다. 장부 정리가 아니었다 — 합성 점수가 `Σ|가중치| × z`이므로 **전 종목 점수가 0.75/1.10 = 0.68배**가 됐고, **발행 등급 8/31건의 라벨이 바뀌었으며**, 하한에 걸려 강제 `관망`이던 5종목이 풀렸다. 순위는 보존되므로 PREREGISTRATION §8.4의 IC·ICIR·분위수 스프레드는 영향이 없다 — 바뀐 것은 표시되는 버킷뿐이다. [PREREGISTRATION §R](PREREGISTRATION.md)에 기록.

> [!note]
> **바깥 등급이 더 멀어졌고, 이건 미해결이다.** 합성 점수의 스케일이 총 가중치를 따라가므로 `강한 매수`/`강한 매도`가 시작되는 지점이 균일 z **1.82 → 2.67**로 밀렸다. 컷포인트 재조정은 §8.4가 "분포상의 이유"로 허용하지만, 스케일을 옮긴 바로 그 변경 안에서 같이 하면 나중에 둘을 구분할 수 없게 된다. 측정값 그대로 두고 `test_the_outer_bucket_needs_a_z_of_two_point_seven`으로 고정했다. [MANUAL-TASKS §6](MANUAL-TASKS.md) 캘리브레이션과 함께 다룰 일이다.

**베이크오프가 끝났고 `gpt-5.1`이 비용으로 이겼다 (2026-08-12).** `claude-sonnet-5`와 `gpt-5.1` 둘 다 §7.4의 모든 기준을 통과했다. `gemini-3.5-flash`는 통과하지 못했는데 — 가격 때문이 아니라 무료 티어의 하루 20콜 한도 때문에 `--repeats 1`로 돌려 자기일관성이 "실패"가 아니라 "미측정" 상태였기 때문이다. 통과한 둘 사이에서는 `gpt-5.1`이 유효 신호당 비용이 8.3배 싸고($0.0101 대 $0.0837), MANUAL-TASKS §5의 사전등록 규칙은 통과한 후보 중 싼 쪽을 고른다. sonnet-5의 relevance 우위(0.83 대 0.76, 0.07차)는 진짜고 그걸 근거로 sonnet-5를 뺀 게 아니다 — 규칙은 통과한 후보 중 비용으로 고르지, 누가 더 높은지로 고르지 않는다. 다만 비교 기준이었던 노이즈 바닥값(±0.07, 2026-08-10 `golden recheck`)은 relevance 재정의 이전 값이라 지금 이 격차를 판단하는 데 쓸 수 없다 — 재측정이 필요하고, 재사용도 폐기도 하지 않은 채 [PREREGISTRATION §R](PREREGISTRATION.md)에 미해결로 기록해 뒀다.

**`gpt-5.1`은 하루 만에(2026-08-13) `gpt-5.4`로 교체됐다 — 새 데이터가 아니라 질문을 받고서 드러난 두 가지 공백 때문이다.** 첫째, 원래 베이크오프는 OpenAI 라인업을 제대로 훑은 적이 없었다 — `gpt-5.1`이 뽑힌 건 `gpt-5`가 `temperature=0`을 거부해서 받아주는 다음 버전으로 넘어간 것뿐이었고, 2026-08-11 시점에 이미 나와 있던 `gpt-5.2`·`gpt-5.4`·`gpt-5.5`·`gpt-5.6`은 아무도 확인하지 않았다. 둘째, OpenAI의 데이터 쉐어링 프로그램(Data Controls → Sharing)이 하루 무료 토큰을 준다 — `gpt-5.1`·`gpt-5.2`·`gpt-5.4` 등이 하루 25만 토큰 풀을 공유하고, mini/nano 계열은 250만 토큰까지 공유하는데, **`gpt-5.6` 계열(sol/terra/luna)은 이 풀 어디에도 없다.** 이게 애초에 재검토를 촉발한 가격 비교를 뒤집는다 — `gpt-5.6-luna`의 화제가 됐던 80% 가격 인하(2026-07-30)는 정가로는 싸 보여도, 지금 볼륨에서 무료 티어 대상인 모델보다 실질적으로 더 비싸다. `gpt-5.4`는 §7.4 기준을 통과했고 `gpt-5.1`보다 실질적으로 나았다(relevance 0.78 대 0.76, polarity 0.86 대 0.82, uncertainty 0.55 대 0.43 — 마지막 항목은 노이즈 바닥 ±0.03을 확실히 벗어남) — 비용은 같은 무료 풀 안이라 그대로였다. 그래서 5.1을 대체했다. `gpt-5-nano`와 `gpt-5.4-nano`는 무료 티어 백업 후보로 테스트했지만 둘 다 relevance에서 탈락했고, `gpt-5.6-terra`는 luna·sol이 가격대를 이미 커버해서 중도에 중단했다. 전체 수치는 `config/models.yaml`의 `scoring:` 주석과 [PREREGISTRATION §R](PREREGISTRATION.md) 2026-08-13 항목에.

여기 도달하려면 골든셋 `relevance` 차원을 전량 재라벨링해야 했다. 세 모델이 상관계수 기준(>0.7)을 나란히 못 넘겼는데(0.70/0.67/0.58) — 이건 모델이 아니라 잣대를 가리켰다. `relevance`의 정의가 라벨링 도중(2026-08-07) 바뀌었는데 옛 라벨 일부가 안 따라간 것이다. 100건 전부를 다시 봤다(규칙이 걸어낸 것만이 아니라) — 모델 출력이 어떤 라벨을 재검토할지 고르게 하면 [PREREGISTRATION §R](PREREGISTRATION.md)이 이미 한 번 이름 붙인 순환성이 되기 때문이다. 100건 중 66건이 바뀌었고 대부분 하향이었다. 이 과정에서 분류 오류 두 건도 드러났다 — 두산(000150)과 현대차(005380)가 자기 점수와 다르게 `무관`으로 분류돼 있었다 — 교정했고, 그래서 `redo_influence()`의 68%는 이제 그 함수의 문서가 말하는 뜻이 아니다: 대부분이 규칙이 되돌린 게 아니라 의도적인 전량 재라벨링이다. `review.jsonl`에 기록되는 `review_influence()`의 11%(버킷 변경)는 여전히 원래 재던 것을 잰다.

**스케줄은 최선 노력(best-effort)이고, 이건 가정이 아니라 실측이다.** GitHub은 선언된 실행의 3분의 1 정도만 띄운다. 2026-08-03~07 구간에서 뉴스 워크플로우는 하루 31회를 선언하고 6~10회를 실행했고, **시간 단위 커버리지는 42.6%**(94시간 중 40시간)였다. 기록에 남은 예약 리포트 실행 두 번은 둘 다 몇 시간씩 늦었다. 하위 구조는 전부 이걸 견디도록 만들어져 있다 — `last_closed_session()`이 날짜가 아니라 시계로 실행 대상 세션을 정하고, 아침 리포트는 발행 여부 검사 뒤에 3중으로 예약되며, `check_feed_continuity`는 추측 대신 그 공백이 실제로 얼마를 앗아갔는지 잰다. `etnews_economy` 제거 후 관측된 공백 45개 중 **1개(2.2%)**만 남은 피드 중 가장 짧은 버퍼를 넘겼다. 커버리지 숫자는 무섭지만 실제 유실은 그렇지 않다.

**뉴스 수집기의 경보가 거꾸로 향하고 있었고, 고쳤다 (2026-08-10).** 2026-08-08 밤 `collect-news`가 5회 연속 실패 메일을 보냈고 그중 아무것도 잃은 것이 없었다. `last_run_at`은 마지막으로 쓰인 파일명에서 런 시각을 읽는데, 신규 기사가 없는 런은 파일을 쓰지 않았다 — 그래서 한국 심야 내내 `check_collection_gap`은 마지막 *기사* 이후 시간을 재며 정시에 돌고 있는 수집기에 2.9h, 3.8h, 5.0h, 5.8h를 보고했고, `check_feed_continuity`는 그 모든 런에서 통과했다. 같은 혼동이 종료 코드에서는 반대로 작동했다. 프레임이 비었을 때만 리포트를 봤기 때문에, 피드가 죽은 채 기사를 저장한 런은 — 측정되지 않고 복구도 안 되는 유실인데 — 0으로 끝나고 조용했다. **이제 런은 비어 있든 아니든 수집한 것을 항상 쓰고, 종료 코드는 검증 결과만 말한다.** 커밋 스텝은 `if: always()`가 됐다. 이게 없으면 새 경보가 커밋을 건너뛰어 자기가 경고하던 기사를 파괴한다.

**같은 경보가 다른 방향으로도 틀려 있었고, 그것도 고쳤다 (2026-08-11).** 피드가 응답하지 않는 순간 바로 실패로 쳤다. "확인되지 않은 유실은 측정 불가이고 복구 불가"라는 근거였는데, 앞의 절반만 참이고 그것도 한 시간짜리다. 다음에 응답하는 런이 그 피드의 버퍼를 같은 저장 이력과 비교해서 사고가 무엇을 앗아갔는지 판정한다 — 그 비교는 이미 매번 돌고 있었고, **2026-08-11까지 60런 동안 이 검사의 실패는 전부 침묵 분기였으며 실제 유실을 잰 것은 한 건도 없었다.** 회복 런은 매번 통과했다. 그날 아침 03:05~07:58 KST에 네 번 메일이 왔는데, 전자신문은 13:30Z~21:00Z 사이 아무것도 발행하지 않았고 그 기사들은 22:00Z 런이 전부 회수했다. 그중 셋은 연속이라 §8.5 게이트의 세 번째 조건이 떨어졌을 것이다 — 결함이 아니라 날씨 때문에. **이제 사고는 매 런 기록되고, 실제 유실이 측정되거나 `MAX_FEED_SILENCE`(24h)를 넘어 어떤 런도 판정할 수 없게 됐을 때만 실패한다.** `fetch`도 같은 사건을 두 번 보고하지 않는다. 잘못된 XML은 여전히 즉시 실패다 — 다음 런이 해결해 주지 않으니까 — 반면 연결 실패는 증거를 쥔 검사의 판정을 따른다. 검사가 2주 창이 열리고 한 시간 뒤에 바뀌었으므로 창을 하루 밀어 **2026-08-12 → 2026-08-26**으로 옮겼다. 창 전체가 한 정의 아래 측정돼야 하기 때문이고, 그 시점에 창 안 실행 런이 0건이라 버린 측정은 없다.

**macro 윈도우가 가장 느린 발행자보다 오래 열려 있게 됐다 (2026-08-10).** FRED FX 시리즈 `DEXKOUS`와 `DTWEXBGS`는 일별 시리즈보다 약 일주일 뒤처지고, 아침 런의 `end`는 그것이 읽히는 KST 날짜보다 *하루 이른* UTC 날짜다 — 그래서 8일 윈도우가 이 시리즈들의 마지막 관측 뒤에 열렸고 2026-08-10 브리핑은 `usdkrw has no rows at all`을 달고 나갔다. 월요일마다 똑같이 반복될 일이었다. macro만 30일로 넓히자(`kr_flow`의 KRX 요청 124건 때문에 전역 윈도우는 8일 유지) 비싼 쪽이 드러났다. **`wti` 2026-07-28이 3년치 저장 이력에서 빠져 있는데 FRED는 80.91을 준다** — 짧은 윈도우가 그 날짜를 지나간 뒤 올라온 EIA 값이고, 다시 가져올 것이 남아 있지 않았다. 저장된 macro의 유일한 진짜 구멍이다. 나머지 결측은 전부 Columbus Day와 Veterans Day로, 채권시장은 쉬고 NYSE는 여는 날이다. 브리핑 헤더는 이제 macro 날짜를 따로 적는다. 시장 라인의 USDKRW 값이 옆에 찍힌 가격 날짜보다 으레 오래됐기 때문이다.

**등급 아카이브가 세션을 중복 계상하는 것을 멈췄다 (2026-08-08).** `load_rating_history()`가 `data/ratings/` 아래 parquet 전부를 이어 붙이고 있었다 — **실제 3개 세션에 217행**, 2026-08-06이 네 번 저장됐고 `2026-08-07.parquet`은 KRX가 열리기 전에 실행된 커버리지 0%짜리 31종목이었다. 이제 세션당 최신 버전 하나만 고르고(93행), `write_ratings()`는 리포트가 이미 발행을 거부하는 프레임이면 저장도 거부한다. 아무것도 지우지 않았다 — 밀려난 파일들은 버그가 발행까지 도달했다는 기록으로 디스크에 그대로 남는다.

**한국 뉴스 수집은 이미 동작하고 막힌 게 없다** — `kr_news`가 언론사 RSS 14개를 GitHub Actions로 읽는다 — 장중에는 30분마다, 그 외 시간에는 시간당. 인증 정보가 전혀 필요 없다. 다만 RSS는 소급 수집이 안 되므로, `collect-news.yml`이 기본 브랜치에 올라간 시점부터만 쌓인다.

**KRX 병목은 해소됐다.** `data.krx.co.kr`이 회원제로 바뀌면서 세션 없는 요청에 HTTP 400 `LOGOUT`을 반환했고, 그 결과 투자자별 순매수·공매도 잔고·시가총액·펀더멘털이 모두 막혀 있었다. **등급 가중치의 55%**이고, 모든 종목을 `관망`으로 몰기에 충분한 양이다. 이제 로그인이 되고, 막혀 있던 6개 엔드포인트를 2026-08-04에 실측으로 확인했다 ([API-KEYS.md §0](API-KEYS.md)). 그 위에 `kr_flow`를 올렸고 검증을 통과했다.

**골든셋 라벨링이 끝났다.** 100건 전부가 5차원을 다 갖고 있고, 4개 버킷이 각각 25건이며, `verify`는 규칙 위반 0건을 보고한다. 라벨링은 전부 Ricky 혼자 했다 — 어떤 모델도 값을 제시하거나 고치지 않았고, 베이크오프 전체가 이 성질 위에 서 있다. 자동화가 실제로 기여한 몫은 가정하지 않고 측정했다: **완성된 세트의 8%가 규칙에 걸린 뒤 버킷이 바뀌었고, 14%는 규칙이 되돌려 다시 매긴 점수를 적어도 하나 갖고 있다**(`scripts/golden.py`의 `review_influence`, `redo_influence`). 두 숫자 모두 과소계상이다. 차원 *정의* 자체가 작업 도중에 Claude의 의견을 반영해 두 번 다듬어졌기 때문이고, 이건 [PREREGISTRATION §R](PREREGISTRATION.md)에 기록해 두었다.

**골든셋이 완성됐고 베이크오프가 풀렸다 (2026-08-10).** `golden recheck`가 10건을 하루 뒤 첫 답 없이 다시 매겼고, `verify`가 평균 차이 0.16으로(임계 0.25) 통과한다. 분리력도 좋다 — `|polarity| ≥ 0.5`가 100건 중 50건으로 `verify`가 요구하는 하한의 두 배이고, polarity 평균 +0.04로 긍정 쪽 쏠림이 없다.

재라벨링이 함께 보여준 것은 불일치가 고르게 퍼져 있지 않다는 사실이다. **`forwardness` 하나가 거의 전부를 만든다** — 평균 차이 0.13으로 나머지 네 차원(0.03~0.07)의 두 배이고, ±0.25짜리 이탈이 전부 여기서 나왔으며, 흩어진 게 아니라 방향이 있다(움직인 6건 중 5건이 아래로). 가장 크게 내려간 세 건은 전부 확정됐지만 처음 알려진 사실인데, 이건 그 차원의 힌트 문장이 정확히 반대로 지시하는 경우다. 스키마는 일부러 고치지 않았다 — 완성된 라벨이 보이는 상태에서 정의를 고치는 것은 [PREREGISTRATION §R](PREREGISTRATION.md)이 이미 한 번 선언해야 했던 오염이기 때문이다. 대신 바닥값을 그쪽에 사전 기록했다. 두 모델의 `forwardness` 차이가 0.13보다 작으면 증거가 아니고, 앵커는 라벨을 쓰기 전에 v2 세트에서 고친다.

## 파이프라인 동작 방식

### 하루 실행 흐름

```
  Collector                     ─→  data/raw/YYYY-MM-DD.*     (불변, 덮어쓰기 없음)
      │                                  │
      │  pykrx, DART, 언론사 RSS,        │
      │  SEC EDGAR, FRED, Alpaca         │
      ↓                                  ↓
  엔티티 해석                    ─→  어떤 기사가 어떤 종목에 관한 것인가
      │  결정론적, config/aliases.yaml 기반
      │  애매한 건은 추측하지 않고 버린다
      ↓
  임베딩 (로컬 bge-m3)           ─→  data/embeddings/
      │  ├─ 중복 제거: 코사인 유사도 > 0.92로 한국 언론 재보도를 묶음
      │  └─ 관련성 필터: 하위 컷
      │  기사 1,000~2,000건  →  60~100건 생존
      ↓
  LLM 스코어링 (Stage 2)         ─→  data/scores/    ← 비용이 발생하는 유일한 단계
      │  기사당 5개 차원: relevance, polarity,
      │  intensity, uncertainty, forwardness
      ↓
  피처 계산                      ─→  data/features/
      │  모든 피처는 종목별 252거래일 롤링 z-score
      ↓
  등급 산출 (결정론적)            ─→  강한 매수 … 관망 … 강한 매도, 종목별
      │  z-score 가중합 → 7단계 스케일, LLM 개입 없음
      │  근거 = 그 합에서 가장 큰 항들
      ↓
  리포트 렌더링                  ─→  결정론적 섹션들을 배치
      ↓
  LLM 합성 (Stage 3)             ─→  반증 섹션 + AI 총평
      │  렌더링된 섹션만 읽는다 — 원문 기사는 안 받으므로
      │  다시 스코어링하는 것이 구조적으로 불가능
      ↓
  일관성 가드                    ─→  총평의 모든 등급 라벨을 계산된 등급과 대조.
      │  모순이면 섹션을 드롭하고 사유를 헤더에 기록
      ↓
  전달                          ─→  reports/YYYY-MM-DD-morning.md
                                    vault (git 커밋) + 이메일
```

### 뉴스 파이프라인이 이런 모양인 이유

비싼 단계(LLM 스코어링)가 가장 마지막에, 가장 적은 건수에 대해 돈다. 중복 제거와 관련성 필터를 LLM에서 로컬 임베딩으로 옮긴 이유는 세 가지다. 비용이 0이 되고, 임베딩은 완전히 재현 가능한 반면 LLM은 `temperature=0`에서도 그렇지 않으며, 한국 언론의 재보도는 문장 단위 유사도로 잡는 게 LLM 판단보다 정확하다.

### 브리핑에 담기는 내용

1. **미국장 → 한국장 전이** — 브리핑에서 가장 방어 가능한 정량 콘텐츠이자, LLM이 전혀 개입하지 않는 섹션 중 하나. 미국 섹터 ETF를 한국 섹터에 매핑하고, 각각에 직전 60거래일 롤링 상관계수를 함께 표시한다. 상관이 깨진 관계를 조용히 신뢰하는 대신 눈에 보이게 만든다.
2. **보유·관심 종목 스캔** — 종목당 한 줄. 외국인 수급, 신규 공시, 실적 리비전, 밸류 밴드, 뉴스 급증, 변동성으로 플래그.
3. **뉴스 스코어 집계** — Stage 2 스코어의 종목별 롤업.
4. **캘린더** — 실적 발표, FOMC·CPI, 옵션만기, 배당락.
5. **반증 섹션 (Red Team)** — LLM에게 그날의 결론에 *반대만* 하도록 지시.
6. **방향성 등급** — 모든 종목에 7단계 등급과 그 근거.
7. **섀도 포트폴리오 P&L** — 그 등급대로 매매했다면 어땠을지. 실계좌와 완전히 분리해서 기록. 이게 등급을 단순한 의견이 아니라 반증 가능한 것으로 만든다.
8. **AI 총평** — 위의 전부를 5~8줄로 합성. 30초밖에 없는 독자가 읽을 것. 반증 섹션과 함께 LLM이 쓰는 단 두 섹션 중 하나다. 아래 참조.
9. **중장기 국면** — 장단기 금리차, 달러, 원달러, WTI, 미국 섹터 로테이션의 120일 추세. ①처럼 결정론적이다.

표시 순서는 ID 순서가 아니다. ⑧은 **맨 앞에 표시되지만 맨 마지막에 생성된다** — 나머지 전부를 입력으로 먹기 때문이다. ID는 문서와 코드 전반에서 참조하는 고정 식별자라, 섹션이 추가돼도 번호를 다시 매기지 않는다.

### AI 총평이 정직함을 유지하는 방식

총평은 LLM이 방향성에 대해 산문을 쓰는 유일한 자리다. 이 프로젝트가 다른 모든 곳에서 모델에게 금지하는 바로 그 행위다. 이게 등급이 되어버리지 않도록 세 가지 성질이 받치고 있고, 셋 다 빠지면 안 된다:

- **렌더링된 결정론적 섹션만 읽는다. 원문 기사는 못 본다.** 스코어링은 이미 상류에서 끝났고, 총평은 그걸 다시 할 수 없다.
- **발행 전에 검사받는다.** `src/report/consistency.py`가 산문 속 등급 라벨을 전부 찾아 `config/aliases.yaml`로 종목에 귀속시킨 뒤 계산된 등급과 대조한다. 모순이면 섹션이 드롭되고, 헤더에 그 사실이 적힌다.
- **아무것도 이걸 읽지 않는다.** 피처도, 점수도, 섀도 포트폴리오도, 평가 지표도. 파이프라인의 잎사귀다.

가드는 두 번째 LLM이 아니라 문자열 매칭이다 — 판단을 검증하는 데 판단이 필요하다면 아무것도 검증하지 않는 것과 같다. 가드와 프롬프트는 한 쌍이다. 프롬프트가 7개 등급 라벨을 등급 전용 어휘로 예약하고 일반적인 수급 움직임은 `순매수`·`수급 이탈`로 쓰게 강제하며, 그래서 매칭이 성립한다. 이 규칙이 없으면 `매수`는 평범한 한국어 시장 기사에 끝없이 등장하고 섹션은 매일 드롭될 것이다.

### 등급이 매겨지는 방식

피처 z-score와 집계된 뉴스 polarity의 가중합을 7단계로 구간화한다. 가중치와 구분점은 `config/rating.yaml`에 있다.

| 강한 매수 | 매수 | 약한 매수 | 관망 | 약한 매도 | 매도 | 강한 매도 |
|---|---|---|---|---|---|---|
| ≥ +2.0 | +1.0 | +0.4 | ±0.4 | −0.4 | −1.0 | ≤ −2.0 |

근거는 그 합의 분해다 — 각 항의 `가중치 × z-score`를 큰 순서대로 — 따라서 숫자를 실제로 움직인 게 무엇인지 그대로 보고하며, 숫자와 따로 놀 수가 없다:

```
005930 삼성전자 — 매수 (+1.13)
  · foreign_flow_5d    z=+2.10   기여 +0.63
  · rev_4w             z=+1.20   기여 +0.18
  · rel_strength_20d   z=+0.90   기여 +0.14
  · news_polarity      z=+0.60   기여 +0.12
  · 그 외 3개 항목                기여 +0.065
```

근거는 상위 4개만 나열되므로 잔차 줄이 반드시 필요하다. 없으면 보이는 항들을 더했을 때 `+1.065`가 나와서 표기된 `+1.13`과 맞지 않고, 맞아떨어지지 않는 숫자는 독자에게 검산을 그만두라고 가르친다.

빈약한 근거 위에 세워진 자신만만한 등급은 등급이 없는 것보다 나쁘기 때문에, 두 가지 안전장치를 뒀다:

- 결측 피처는 0으로 채우지 않고 **제외한 뒤 가중치를 재정규화**한다. 0으로 채우면 점수가 `관망` 쪽으로 끌려가면서도 겉보기엔 완전한 정보로 계산된 것처럼 보인다.
- 가중치 커버리지가 50% 미만이면 `관망`으로 강제하고 어떤 입력이 빠졌는지 명시한다.

### 자기기만을 막는 두 가지 규칙

**룩어헤드 금지.** 시점 `t`에 계산되는 피처는 `t` 이후 타임스탬프를 가진 데이터를 절대 쓰지 않는다. 피처를 계산하는 모든 함수는 명시적인 `as_of` 파라미터를 받는다 — 경계 없이 "최신" 데이터를 읽는 함수는 편의 기능이 아니라 버그다. 뉴스는 발행 타임스탬프로 조인하고, 장중 발행된 뉴스는 *다음* 세션 시가에만 체결 가능한 것으로 가정한다.

**정규화.** 모든 피처는 종목별 252거래일 롤링 z-score다. 절대값을 종목 간에 비교하는 일은 없다.

### 완성된 모듈이 실제로 하는 일

**`src/util/session.py`** — 저장은 전부 UTC, 표시만 KST. 시장 세션은 하드코딩된 휴장일 목록이 아니라 `pandas_market_calendars`에서 가져온다. 한국의 음력 공휴일(설날, 추석)은 매년 날짜가 바뀌기 때문에 이게 중요하다. 미국장 마감 시각은 *유도*되므로, 코드 어디에도 그 숫자가 없는 채로 서머타임 기간엔 05:00 KST, 그 외엔 06:00 KST로 정확히 떨어진다. `next_tradeable_open()`이 룩어헤드 규칙을 구현한다.

**`src/collectors/validate.py`** — 모든 collector는 4가지 검사를 통과해야 하고, 이 검사는 수집 로직보다 **먼저** 작성된다. 스키마(컬럼명과 dtype), 선언된 임계값 대비 결측치 비율, 휴장일을 제외한 거래일 연속성, 그리고 하드코딩된 알려진 값 최소 1건과의 대조. 결과는 예외를 던지는 게 아니라 *기록*된다 — 실패한 collector는 실패를 기록하고 파이프라인을 계속 돌리므로, 헤더에 결측이 명시된 부분 리포트라도 발행된다.

**`src/report/rating.py`** — 피처 z-score를 7단계 방향성 등급과 그 등급을 만든 분해 내역으로 바꾼다. 순수 산술이고 완전히 재현 가능하다. 같은 입력이면 항상 같은 등급이 나오는데, LLM이 쓴 등급은 이걸 보장할 수 없다.

**`src/report/consistency.py`** — AI 총평에 대한 가드. LLM이 쓴 산문에서 등급 라벨을 전부 찾아, 별칭 사전으로 종목에 귀속시킨 뒤 계산된 등급과 대조한다. 흥미로운 부분은 *매칭하지 않는* 쪽이다. `순매수`, `매수세`, `매도호가`는 등급 주장이 아니라 일반적인 시장 어휘이므로, 앞뒤에 한글 음절이 붙은 라벨은 거부한다 — 다만 뒤에 붙는 조사(`매수는`, `매수로`)는 허용한다. 조사는 닫힌 집합이지만 복합명사는 그렇지 않기 때문이다.

**`scripts/config_helper.py`** — Ricky가 손으로 쓰는 config 파일 두 개를 위한 운영 도구. `find`는 회사명을 종목코드·KRX 업종으로 바꾸고, `scaffold`는 별칭 항목의 기계적인 절반을 gitignore된 워크시트에 채워 넣고, `audit`은 이미 수집된 뉴스에 `aliases.yaml`을 돌려 매칭된 헤드라인까지 보여준다. `config/aliases.yaml`을 직접 쓰지 않고 `aliases` 값을 제안하지도 않는다 — 커버리지만 줄일 뿐 오귀속은 불가능한 `exclude`와 `ambiguous_parents`만 채운다.

**`src/util/config.py`** — 로딩이 곧 검증이다. 손으로 편집할 때 저지르기 쉽고 나중에 발견하기는 불가능한 실수들을 거부한다. 두 종목이 같은 별칭을 주장하는 경우, 별칭이 자기 자신의 exclude 목록에도 있는 경우, 따옴표 없는 종목코드, 그리고 순서가 뒤집힌 등급 구분점.

> **따옴표 없는 종목코드 함정.** YAML은 앞자리가 0인 맨숫자를 8진수로 읽는다. 따옴표 없는 `000660`(SK하이닉스)은 조용히 정수 `432`가 된다. `005930`은 `9`가 유효한 8진수 숫자가 아니라서 우연히 살아남는다 — 그래서 이 실패는 일관성이 없고 놓치기 매우 쉽다. 종목코드는 항상 따옴표로 감쌀 것. 로더가 따옴표 없는 코드를 설명이 담긴 에러로 거부한다.

| 9 | 피처 계산 | ✅ 등급 피처 7개 중 5개, 가중치 0.75/1.10 |
| 10 | 리포트 렌더러 + 발송 | ✅ vault + 이메일 작동. 2026-08-03~2026-08-12 브리핑 10건 |
| 11 | 일일 수집 + 리포트 워크플로우 | ✅ **클라우드 왕복 성공 2026-08-06** — 수집 5종·렌더·이메일·커밋 |

**파이프라인이 스스로 돈다.** 사람이 손대지 않아도 수집 → 해석 → 계산 → 등급 →
문서 → 이메일이 클라우드에서 하루 두 번 완주한다. 증거는 셋이다: 받은편지함의
브리핑, `reports/`의 문서, GitHub Actions 봇이 남긴 데이터 커밋.

**번인은 그 자체가 성과를 내고 있다.** 12단계의 목적은 스케줄이 뜨는지 보는 것이지만,
실제로 잡힌 것은 코드 결함이었다 — 늦게 뜬 cron이 열리지도 않은 세션의 등급을 매겨
전 종목을 `관망`으로 발행한 일, 마크다운이 그대로 나간 이메일, 러너 배정 실패로
날아간 뉴스 8시간, 그리고 연결 실패한 피드를 조용히 통과시키던 연속성 검사. 넷 다
실측으로 확인하고 수정했다. 라이브가 아니었으면 넷 다 못 봤을 것들이다.

남은 것은 6단계(임베딩 파이프라인)다. 7·8단계(골든셋, 베이크오프)는 2026-08-12에
끝났다. 등급이 숫자를 내는 데는 필요 없는 부분이지만, `news_polarity`에는 필요하다.

### 백필이 들어왔고 z-score가 실제로 나온다

`kr_flow`가 2026-08-06에 끝났다. **22,528행, 31종목, 728세션**, 2023-08-03부터
2026-08-03까지이고 결측값은 없다. 수급 항등식 — 외국인·기관·개인·기타법인의
순매수 합이 0이 되는 성질로, 구조상 반드시 성립하므로 투자자 컬럼이 잘못
매핑됐을 때 가장 싸게 잡아내는 검출기다 — 이 **22,528행 전부에서** 성립한다.

이력이 채워지자 피처가 `NaN`을 벗어났다. 아래 수치는 같은 날 실측이고, 이후 KRX
세션마다 종목당 1씩 늘어난다:

| 피처 | 원값 | z-score |
|---|---:|---:|
| `foreign_flow_5d` | 22,383 | 14,067 |
| `inst_flow_5d` | 22,383 | 14,067 |
| `short_ratio` | 22,528 | 14,408 |
| `rel_strength_20d` | 18,368 | 11,816 |
| `valuation_band` | 0 | 0 |

`valuation_band`가 비어 있는 건 756세션이 필요한데 창이 아직 거기 못 미치기
때문이다 — 아래 보류된 결정 참조. 454910이 다른 종목보다 정확히 **40세션** 뒤진
것은 2023-10-05 상장, 즉 창이 열리고 40세션 뒤에 시작했기 때문이라 **없는 이력이지
빠진 이력이 아니다.** 세션 총량은 매 KRX 세션마다 움직이지만 이 40은 안 움직인다.

`scripts/backfill.py`는 계속 재개 가능하다. KRX는 주소 단위로 제한을 건다 —
대략 250요청이면 몇 시간 동안 JSON 대신 HTML 오류 페이지를 준다 — 그리고
`kr_flow`는 1년치당 124요청이라 재실행도 여러 창에 걸쳐 채워진다.

### Ricky가 결정할 것 두 가지

**`rev_4w`는 데이터 소스가 없다.** SPEC §5는 **컨센서스 EPS**(증권사 전망치)의
4주 변화로 정의하는데, pykrx의 `EPS`는 후행 실적이다. 바꿔치면 피처처럼 보이는
틀린 숫자가 나온다. 제대로 하려면 전망치 벤더(FnGuide, QuantiWise)가 필요하다.
가중치 0.15. 없어도 `rate()`가 재정규화한다.

**`valuation_band`는 저절로 켜지고, 4년치 백필은 시간만 앞당긴다.** 756세션 PBR
백분위인데, 저장된 창이 2026-08-07 기준 732세션이고 KRX 세션마다 1씩 늘어난다 —
백필을 아예 안 해도 30종목은 **2026-09-11**, 454910은 **2026-11-12**에 756에
도달한다. 백필을 1년 늘리면 약 4주 앞당겨지고 비용은 KRX 요청 124회다. 가중치가
0.05라는 점이 기다리는 쪽을 기본값으로 만든다.

### 왜 9단계를, 그리고 10단계까지 6~8단계보다 먼저 하나

등급 피처 중 **LLM이 필요한 건 `news_polarity`(0.20) 하나뿐이다.** 9단계에서
만든 다섯 개가 가중치 1.10 중 0.75를 차지하고 `min_weight_coverage: 0.5`를
넘으므로, 임베딩·골든셋·베이크오프 없이도 결정론적인 실제 등급이 나온다.
순서를 뒤집은 이유가 이것이다.

[2026-08-06 검토](notes/review-2026-08-06.md)에서 같은 논리를 10단계까지
확장했다. PREREGISTRATION의 2주 검증 항목은 두 갈래로 갈린다 — 파이프라인
무결성·데이터 정합성·엔티티 정확도·브리핑을 실제로 읽는지는 **10~12단계**가
있어야 하고, 모델 간 일치도와 골든셋 성능은 6~8단계가 있어야 한다. LLM 단계를
먼저 지으면 그 2주 시계가 시작되지 않는다.

살아 있는 결함도 이걸로 닫힌다. `check_feed_continuity`는 한 피드
(`etnews_economy`)가 마지막 저장 기사보다 5.3시간 밀려났음을 정확히 검출했지만,
그 결과가 아무도 읽지 않는 GitHub Actions 로그로만 갔다. CLAUDE.md는 결측
데이터가 **로그가 아니라 리포트 헤더에** 떠야 한다고 못박는다 — 그 헤더가
10단계에서 나온다.

남는 대신 GitHub이 실패 메일을 보낸다. 상세 내용은 여전히 실행 로그를 열어야
보인다. L1은 남아 있고 비용이 없다.

## 평가

평가 기준은 데이터가 존재하기 전인 2026-08-02에 [PREREGISTRATION.md](PREREGISTRATION.md)로 고정됐다. 수정은 날짜, 이유, 그리고 수정 시점에 데이터를 이미 봤는지 여부와 함께 그 문서에 기록된다.

| 게이트 | 기준 | 미달 시 |
|---|---|---|
| 2주<br>2026-08-12 → 2026-08-26 | 파이프라인 무중단, 데이터 정합성 오류 0건, `ambiguous` < 30%, 모델간 polarity 상관 > 0.5 | 신호 작업 중단, 측정 레이어 수리 |
| 3개월 | ICIR > 0.3, 섀도 포트폴리오가 KODEX 200 buy&hold 대비 우위 | 신호 로직 폐기 후 재설계 |
| 6개월 | 수수료·거래세·슬리피지 반영 후에도 위 조건 유지 | 프로젝트 종료, 인덱스로 전환 |

**2주로는 신호가 작동하는지 측정할 수 없다.** 적중률 55%를 50%와 구분하려면 독립 관측치가 약 800건 필요한데, 30종목 2주치는 시장 베타가 횡단면 독립성을 먹어치우고 나면 유효 표본이 60~100건에 불과하다. 그래서 초기 게이트는 예측 정확도가 아니라 *측정 안정성*을 잰다 — 서로 다른 모델 3개가 같은 기사를 채점했을 때 서로 일치하는지. 일치하지 않으면 그 스코어는 모델 고유의 노이즈이고, 아직 검증할 가치가 있는 대상이 존재하지 않는다는 뜻이다.

**"무중단"이 무엇인지도 적어 뒀다.** 뜬 실행은 전부 실행 파일을 남길 것, 설명되지 않은 `check_feed_continuity` 실패가 없을 것, 같은 원인으로 연속 2회 검증 실패가 없을 것 — [§8.5](PREREGISTRATION.md)가 전문을 정의하고 실제 사건들로 기준선을 고정한다. 가운데 조건은 2026-08-11에 측정 가능해졌다. 응답하지 않은 피드를 다음에 응답하는 런이 판정하게 되면서, 이 기준은 파이프라인이 고칠 수 있는 원인만 세고 파이프라인이 처한 날씨는 세지 않는다. 선언 대비 실제 실행률은 판정과 함께 보고하되 기준으로 삼지 않는다. 실행을 흘리는 것은 GitHub 스케줄러이지 이 파이프라인이 아니기 때문이다. 모델간 상관 기준은 8단계 베이크오프가 필요하므로 게이트는 두 부분으로 나누어 읽고, 둘 다 통과해야 통과다.

**"데이터 정합성 오류 0건"은 부재가 아니라 모순을 뜻한다.** 세는 것은 네 가지다 — `schema`, `structural_invariants`, `flow_identity`, 그리고 Alpaca와 Tiingo의 종가 비교. 커밋된 리포트 헤더에서 읽는다. `missing_ratio`와 `trading_day_continuity`는 제외하며 근거는 [§8.5](PREREGISTRATION.md)에 있다 — 후자는 한때 Tiingo rate-limit 하나로 25건이 동시에 떴기 때문이다. 목록은 건수를 알기 전에 썼고, 현재까지 기록으로는 0건이다.
